# 共享设计基础（明道云 / Nocoly）

本文件只定义明道云与 Nocoly 共同使用的设计理念、色彩 Token、排版层级和视觉禁忌。生成任何品牌物料都必须读取本文件，再按 `SKILL.md` 的品牌路由只读取 `references/brands/mingdao.md` 或 `references/brands/nocoly.md`；不要在本文件中加入品牌专属 Logo、字体家族或命名规则。

---

## 0. 视觉 DNA 总览

明道云与 Nocoly 的共享视觉 DNA 由四个层级构成：

1. **品牌内核**：决定视觉要传递的定位、价值和性格（核心设计理念见 0.1）。
2. **核心识别系统**：建立最直接的品牌识别，包括 Logo、色彩与字体。
3. **品牌表达系统**：通过图形、版式、影像、图标和动态形成完整的视觉语言。
4. **应用与治理规则**：规定各元素如何组合、延展和持续维护。

### 0.1 核心设计理念
**形式为功能服务**：画面中出现的所有元素都必须有其存在的必要性——不为装饰、隐喻或概念符号化而存在的元素一律不用。

**充分信任留白与信息疏密**：视觉分组首先由信息本身的布局、间距、字号和字重完成。只要留白与元素疏密已经能让阅读顺序和分组关系成立，就不得再添加分割线、色块、边框或其他纯视觉结构元素做重复分组。

**添加前的必要性提问**：每次准备加入线、色块、图标、卡片背景等纯视觉结构元素之前，必须先问：

> 如果去掉它，信息会看不懂吗？

如果答案是否定的，就不添加。仅当去掉该元素会直接损害信息理解、可读性、操作识别或必要的物理功能时，才允许使用，并且只使用完成该功能所需的最小形式。

这是"品牌内核"层最核心的表达方式：品牌的深层主张**不通过具体符号或图案直接图解**，而是通过视觉系统本身的严谨、克制、精确来隐性传递。概念本身留给沟通内容去显性表达，视觉只负责"如何呈现"，不负责"图解是什么"。

**核心表达手法**：
- **严谨的网格系统**：所有版式基于网格对齐，比例关系明确、可推导，禁止随意或纯感性的自由构图
- **字体排版的精确感**：字号、字重、行距、字间距的选择服从信息层级和阅读逻辑，而非追求视觉效果本身

> **设计参照**：色彩配比、字号体系、留白逻辑优先参照 Dieter Rams / Braun 的数学化、模数化设计传统——字号阶梯按固定比例推导、间距按网格模数计算、色彩作为语义信号（标记关键操作/信息）而非大面积装饰，字号设计的"精确感"是当前最需要落地的部分。

**禁止**：为表达某个抽象概念（如"科技感""智能""连接""AI"）而添加装饰性图形、隐喻符号或流行视觉元素（渐变光效、抽象几何点缀、连接线/节点插画、投影/阴影等）——任何元素一旦不服务于具体功能（对齐、层级、可读性、留白节奏），即视为违反本条设计理念。投影效果的具体规则见第 2 节。

# 1. 共享视觉 Token
## 1.1 品牌色（已确定，2026-07-13）

明道云与 Nocoly 共享以下色彩 Token。三色体系中的**三个颜色均可作为单一满版背景色使用**（不是"主色大面积+辅助点缀"的传统主辅关系，三者地位对等，各自都能独立撑起一整张物料的背景）。**纯白 #FFFFFF 额外允许作为第四种满版背景**（不算在三色体系内，但同样允许独立撑起整张物料背景，2026-07-21 确定，起因是公众号头条封面的白底实验版）。

| 色彩角色 | 名称 | HEX | RGB | CMYK |
|--------|------|-----|-----|------|
| 主色 | 品牌蓝 | #1677FF | 22, 119, 255 | 91, 53, 0, 0 |
| 辅助色 | 云灰 | #E0E5EC | 224, 229, 236 | 5, 3, 0, 7 |
| 点缀色 | 墨蓝 | #082C5E | 8, 44, 94 | 91, 53, 0, 63 |
| （额外允许） | 纯白 | #FFFFFF | 255, 255, 255 | 0, 0, 0, 0 |

**作为满版背景时的文字配色规则**（已用 WCAG 对比度验证，禁止自行搭配）：
| 背景色 | 正文/小字文字色 | 大标题/大字文字色 |
|---|---|---|
| 主色 #1677FF | 白色（对比度 4.10，接近临界值，正文尽量简短） | 白色或近黑均可 |
| 辅助色 #E0E5EC | 点缀色 #082C5E（对比度 10.83）或近黑 #151A21（对比度 13.81） | 同左 |
| 点缀色 #082C5E | 白色（对比度 13.71） | 白色 |
| 纯白 #FFFFFF | 近黑 #151A21（对比度 17.47） | 近黑 #151A21 或点缀色 #082C5E（对比度 13.71）均可 |

**禁止**：主色文字（#1677FF）直接放在辅助色或点缀色背景上做正文（对比度仅 3.24 / 3.34，只够大标题级别使用，正文会不合规）；品牌蓝文字放在纯白背景上做正文同理不合规（对比度 4.10，仅短标题/标签可用）。

**满版背景选哪个颜色（AI 推荐依据，不是必须遵守的硬规定）**：四色都能独立撑起背景，AI 先按物料场合、内容密度和传播目标用下表形成推荐。普通内容页和不以背景色构成主视觉的物料可以直接采用；海报类单页主视觉、PPT 封面和白皮书封面须按 `generation-checklist-common.md` 把推荐项置于颜色选项首位，等待用户确认后再生成。本节是颜色选项与推荐理由的唯一权威来源，各物料文件不重复定义另一套色值或场景映射。

| 场合 | 推荐背景 | 理由 |
|---|---|---|
| 正式论坛、发布会、行业峰会 | 点缀色 #082C5E 墨蓝 | 更庄重、更有分量感 |
| 嘉年华、团建、内部活动 | 主色 #1677FF 品牌蓝 | 更有活力、识别度最高 |
| 信息密度高、需要突出大段文字内容 | 辅助色 #E0E5EC 云灰 | 背景更安静，文字对比度最好，长文案更易读 |
| 强调编辑感/克制感、希望文字对比度拉满 | 纯白 #FFFFFF | 对比度全场景最高（近黑文字 17.47），最贴近"留白即容器"的克制调性 |

**单页主导色与同组配色规则**：

- **每页只设一个主导色**：主导色是该页承担最大品牌识别与视觉权重的颜色，不等同于上表色彩角色中固定命名为“主色”的品牌蓝。品牌蓝、云灰、墨蓝虽然都能各自独立撑起物料，但这不代表要在同一页轮流展示三种颜色。纯白、近黑和文字与图形功能色阶作为中性色或功能色使用时，不与主导色并列；白底页面可以只使用一个主导品牌色，也可以在不损害品牌识别的场景中保持纯白与中性色。
- **点缀色限额**：一页最多引入一种非主导品牌色，用于个别元素的强调、对比或必要分组；其有明显面积的元素总和原则上不超过页面视觉面积的约 20%，且不得形成第二视觉中心。面积统计包括色块、卡片背景、整行或整列底色等；小字、图标和细线不机械计入面积，但仍需检查其整体视觉权重。云灰 `#E0E5EC` 作为大面积背景时按品牌色统计，仅作为细分割线等功能元素时按功能中性色处理。
- **多页物料默认统一**：整份多页物料默认沿用同一个主导色。章节变化本身不构成换色理由；只有用户明确要求用颜色区分章节时才允许按章节切换主导色，并且同一章节内部保持稳定，禁止逐页轮换品牌三色。
- **同组元素继承同一配色**：网格、卡片组、列表组、图标组等同一组中的同级单元，背景、标题、边框、图标容器和其他同类元素应采用一致的颜色角色与组合方式。先由整页确定主导色，再由组确定配色，子元素继承组的配色；禁止按单元序号或元素序号轮换品牌蓝、云灰、墨蓝。
- **AI 可以主动分组**：用户没有明确提出分组时，AI 可以根据内容语义和易读性主动形成可解释的分组。优先使用位置与间距建立分组；仍需增强辨识时，可在“分组标题”和“颜色分组”中任选其一。无法抽象出准确标题或页面空间不足时，允许直接用颜色暗示分组，不强制添加标题；两种手段不默认叠加。
- **颜色分组必须保持组内一致**：使用颜色区分分组时，颜色必须对应真实、可说明的信息关系，如责任主体、阶段、状态或类别；按整行、整列或完整子组统一着色，不能为了丰富画面而在相邻单元间交替换色。颜色分组仍须遵守“一种非主导品牌色、约 20%”的限额。
- **单个单元异化**：同一网格组默认最多允许一个单元使用不同配色，并且必须对应明确的重点、例外、推荐项、当前状态、风险项等信息语义。AI 可以主动判断，但须在自检记录中说明理由；多个单元都需要异化时，应先检查它们是否应被重新归为一个独立分组。
- **两列对比例外**：两列数据存在真实对比关系时，可以分别使用主导色与非主导色。默认只在列头、关键数字、标识条等局部元素上建立颜色对应，列体保持中性，并继续遵守约 20% 的限额。只有用户明确要求强对比，或不用整列异色底会显著降低理解效率时，才允许两列使用大面积异色背景并突破该限额；必须在自检中记录例外理由。
- **数据可视化例外**：图表可以因多个真实数据系列使用多色，但颜色映射必须稳定，并优先使用 1.1.2 节品牌蓝色阶。图表配色不得扩散到页面标题、卡片、网格组件等非数据元素，不能借图表例外恢复页面级的三色轮换。

**局部强调的配色规则**：
- 标题/正文中强调某一部分文字时（比如两行标题里强调其中一行），**用色块反转（背景色和文字色互换）**，禁止在同一背景上换一个同色系的浅/深色调文字来做强调——那样会降低对比度，反而更不显眼。
- 色块反转两个方向的对比度是同一个值（比如点缀色底配白字、和白底配点缀色文字，对比度都是 13.71），互换不会牺牲可读性。这条是手法安全性的硬规则；具体在什么场合要不要做局部强调、强调哪一部分，仍按各物料的实际需要判断，不强制默认使用。
- 色块反转仍须服从上方“每页只设一个主导色”和“点缀色限额”，不得让反转后的色块形成第二视觉中心。
- **功能色（成功/警告/错误等系统状态语义色）不默认使用**：这类颜色独立于品牌色板之外，只有在具体设计场景中确认存在真实的系统状态语义需求时，才主动与用户确认后引入，不能仅因为"想要更抢眼的强调效果"而擅自新增——那种情况应优先用色块反转或面积分工解决。

**深色背景次要元素的不透明度规则**（已用 WCAG 对比度验证，数值不得自行更改）：深色背景上的白色（#FFFFFF）次要文字/图形元素，允许用不透明度弱化视觉层级（区别于不透明度100%的主标题），但必须先验证对比度， 参考不透明度表如下：

| 背景 | 用途 | 最低不透明度 | 对应对比度 | 临界值参考 |
|---|---|---|---|---|
| 点缀色 #082C5E | 正文/小字级次要文字 | 60% | 5.85 | 50% 时对比度恰为 4.5:1（AA 正文临界值），60% 预留安全余量 |
| 点缀色 #082C5E | 大字/图标等非正文元素 | 40% | 3.41 | 35.6% 时对比度恰为 3:1（AA 大字/图形临界值），40% 预留安全余量 |
| 主色 #1677FF | 次要文字/图标等元素 | 80% | 3.17 | 75.9% 时对比度恰为 3:1，80% 预留安全余量 |

**主色 #1677FF 背景的特殊限制**：不透明度只会让对比度相对满不透明度状态单调下降，而主色背景满不透明度（100%）时白字对比度本来就只有 4.10，低于 4.5:1 的正文门槛——所以**正文/小字级次要文字在主色背景上完全不能用不透明度弱化，无论调到多少都不可能达标**，只能用字号/字重区分层级。但 4.10 本身高于 3:1，大字/图标级别有余量往下调（见上表 80% 档），这部分是允许的，不要一刀切禁掉。

纯白 #FFFFFF、辅助色 #E0E5EC 等浅色背景本身用近黑/点缀色文字，不适用"白色降不透明度"这套逻辑，不要套用本条。

如需要用到本条以外的不透明度数值（比如其他背景色、或上表未覆盖的场景），必须重新按 WCAG 公式验证达标后才能使用，验证通过的数值应更新回本文件复用，不允许每次生成物料时各自取一个新数值。

## 1.2 排版系统

字体家族、语言映射、可用字重与缺失字体处理属于品牌配置：明道云读取 `references/brands/mingdao.md`，Nocoly 读取 `references/brands/nocoly.md`。本节只定义两个品牌共同遵守的排版层级和字号规则。

### 排版原则
- 同一画面内原则上不超过两个字体家族；
- 优先使用字重和字号建立层级，谨慎使用倾斜和描边，禁止使用阴影；
- 中文与英文混排时，应校正字号、基线和字间距；
- 大标题可适当紧凑，正文保持舒适的字间距与行高；


### 字体层级

- **主标题**：承担核心观点，短、明确、有视觉力量；
- **副标题**：补充背景或价值，不与主标题竞争；
- **模块标题**：建立内容结构，保持统一字重与间距；
- **正文**：优先保证阅读效率，避免过细字重；
- **注释与说明**：弱化但仍需满足可读性要求；
- **数据与强调信息**：可通过字重、字号或品牌色强化，不同时叠加过多方式。
字号体系的关键不是建立更多级别，而是：
**用尽可能少的字号，表达足够清楚的区别。**

**字号比例参考**（以"操作名称或正文"为基准 1 倍，按固定比例向上下推导）：

| 层级 | 示例比例 |
| --- | --- |
| 核心数字或一级信息 | 1.5–2 倍 |
| 操作名称或正文 | 1 倍 |
| 辅助参数 | 0.7–0.8 倍 |

比如以 14 为基础字号，可以得到：
- 辅助信息：10 或 11
- 正文 / 操作标签：14
- 重要信息：20 或 22
- 极少数核心数字：28

**遵守四条约束原则**：
1. 一个界面尽量不超过四种字号；
2. 正文或操作文字作为基准，而不是标题；
3. 通过留白和对齐完成的层级，不再用字号重复强化；
4. 最大字号只留给真正影响用户判断的信息。

### 字号下限（其他文件引用「最小字号」时指的就是这一条）

**本体系不设跨物料通用的绝对像素下限，下限由比例体系给出：任何文字都不得小于「辅助参数」档，即 0.7 × 该物料的正文基准字号。** 正文基准本身随画布尺寸变化（如 16:9 PPT 的正文基准是 14pt，下限即 10pt），所以下限也是随画布浮动的相对值，不是一个写死的数字。

排版空间不够时的处理顺序：**先减内容、再调容器高度或列数，最后才动字号**；压到 0.7 倍仍放不下，说明该页内容超载，应拆页或精简文案，不允许继续往下压。

`references/materials/ppt/workflow.md`、`references/materials/ppt/export-qa.md` 中“不得突破最小字号”均指本条。

### 中文折行与孤字

中文的每个字都可能成为断行点，自动折行容易让最后一行只剩一两个字。

- 正文段落使用 `text-wrap: pretty`，禁止使用 `balance`。`balance` 会将整段压成等长短行，可能使文字块只占约七成栏宽并在右侧形成大锯齿；只有行数少的标题适合使用 `balance`。
- `pretty` 仍无法消除孤字时，在文案中使用 `<br>` 手动断行。
- 按最后一行的估算字数验收，不按其占栏宽的百分比验收。不同尺寸物料的栏宽差异过大，同一百分比门槛无法稳定识别孤字。
- 多行文本的最后一行中文少于 5 字，或英文少于 8 个字符（约一个短词）时，判定为不合格。

HTML 稿可选内联以下自检片段：

```js
// 孤字检查：多行文本块的最后一行不许只剩一小截
document.querySelectorAll('.panel *').forEach(el => {
  if (el.tagName === 'H1' || el.tagName === 'H2') return;       // 标题的短末行多半是手动断的
  if (![...el.children].every(c => c.tagName === 'BR')) return; // 只查文本叶子
  const t = (el.textContent || '').trim();
  if (!t) return;
  const rg = document.createRange();
  rg.selectNodeContents(el);
  const lines = [...rg.getClientRects()].filter(x => x.width > 0); // 一行一个矩形
  if (lines.length < 2) return;
  const sum = lines.reduce((a, x) => a + x.width, 0);
  const chars = lines[lines.length - 1].width / (sum / t.length);  // 最后一行约几个字
  const hasCJK = /[㐀-鿿　-〿＀-￯]/.test(t);
  if (chars < (hasCJK ? 5 : 8)) console.warn('孤字', chars.toFixed(1), t.slice(-16));
});
```
