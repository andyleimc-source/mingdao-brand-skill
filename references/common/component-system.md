# 共享组件系统

本文件定义明道云与 Nocoly 跨物料共用的组件语义、内容槽位、组合关系和视觉角色。具体尺寸、坐标、排版算法和分页行为由物料适配层定义；PPT 读取 `references/materials/ppt/components.md`。白皮书当前只有 `references/materials/whitepaper/layouts.md` 的页面与长文档排版规范，尚未建立组件适配层。

## 1. 使用原则

- 按信息职责选择组件，不按页面用途或视觉外观建立重复组件。
- 共享组件只定义稳定语义和组合约束，不包含 PPT 的 LU、白皮书的 mm / pt 或任何渲染器专属代码。
- 组件内容与视觉外框分离。Feature、Stat、Quote 等负责表达内容；Surface / Card 负责背景、描边、圆角和内边距。
- 组件不自行决定页面位置。页面骨架或物料排版系统先分配区域，物料适配层再选择合法几何配方。
- 明道云与 Nocoly 共用组件体系；字体、Logo、语言映射和品牌身份从当前品牌配置注入。
- 首版保持最小组件集。Profile、Logo Wall、客户案例卡等复合形式先用已有组件组合，重复出现并验证有效后再正式收录。

## 2. 公开组件

| 组件 | 信息职责 | 不用于 |
|---|---|---|
| Narrative | 承载一般叙述、列表、短结论或品牌声明 | 真实引用、核心数据、步骤流程 |
| Feature | 解释一个功能、特征、原则或观点 | 单纯为了出现图标而包装文字 |
| Stat | 强调一个有明确含义的数据或数值 | 没有数据语义的装饰大字 |
| Quote | 呈现真实引用、客户原话或来源明确的观点 | 普通强调句 |
| Media | 呈现信息型或表现型视觉 | 用拉伸、随意裁切填满区域 |
| Stepper | 呈现具有真实先后关系的线性步骤或流程 | 纯并列信息、分支、回流、泳道 |
| Group | 组织具有共同语义的内容 | 仅为增加一层视觉外框 |
| Collection | 排列多个同级、同构组件 | 混装无共同结构的内容 |
| Surface / Card | 为内容提供必要的视觉边界或强调 | 固定的“标题＋说明”内容模板 |

### 2.1 Narrative

共享文字角色而不是固定 Text Pair：

| 槽位 | 必选 | 说明 |
|---|---|---|
| Heading | 否 | 建立当前内容块的主题 |
| Body | 否 | 一段或多段正文 |
| List | 否 | 真正并列或有序的条目 |

允许的首版组合：

- Heading
- Heading + Body
- Heading + List
- Body
- Body + List
- List

Narrative 至少包含一个槽位。物料适配层提供：

- **Standard**：一般叙述，默认使用起始侧对齐。
- **Focus**：短结论、品牌声明、章节语句或页面核心观点；同一页面默认只使用一个。

### 2.2 Feature

| 槽位 | 必选 | 说明 |
|---|---|---|
| Title | 是 | 功能、特征、原则或观点名称 |
| Description | 否 | 解释或补充 |
| Icon | 否 | 只有能提高辨认效率时使用 |
| Supporting Info | 否 | 必要的辅助信息，不作为塞不下时的默认删除项 |

Icon 不必要或没有准确图标时使用无图标形式；具体配方由物料适配层定义。不得为了保持形式完整添加无意义图标。

### 2.3 Stat

| 槽位 | 必选 | 说明 |
|---|---|---|
| Value | 是 | 数据、比例、金额或其他可验证数值 |
| Label | 是 | 解释数值含义 |
| Context | 否 | 时间范围、样本或背景 |
| Change / Unit | 否 | 仅在真实数据需要时使用 |

一个 Stat 只表达一个主要数值。多个同级 Stat 交给 Collection 排列。

### 2.4 Quote

| 槽位 | 必选 | 说明 |
|---|---|---|
| Quote | 是 | 原始引用内容 |
| Attribution | 否 | 说话者或作者 |
| Role / Source | 否 | 身份、机构或来源 |

没有真实来源时不编造 Attribution。普通强调句使用 Narrative.Focus。

### 2.5 Media

| 槽位 | 必选 | 说明 |
|---|---|---|
| Asset | 是 | 图片、视频封面或其他视觉资产 |
| Internal Description | 是 | 生成与无障碍记录使用，页面不一定显示 |
| Caption | 否 | 页面需要解释视觉时显示 |
| Source | 否 | 只有确有展示需求时显示 |

按视觉功能选择：

- **Contain**：产品截图、界面、表格、图表、流程示意等信息型视觉；完整保留信息和原始比例。
- **Cover**：人物、场景照片和表现型插画；允许按目标区域裁切，但必须保护主体和关键内容。

边框、圆角和承托背景不属于 Media 的必备结构，需要边界时在外层应用 Surface / Card。

### 2.6 Stepper

Stepper 是完整的线性步骤流程组件，不另外暴露独立 Step 组件。

```text
Stepper
├── Step Node
├── Connector
├── Step Node
├── Connector
└── Step Node
```

单个 Step Node 的槽位：

| 槽位 | 必选 | 说明 |
|---|---|---|
| Index / Marker | 是 | 由组件自动生成 |
| Title | 是 | 当前步骤或阶段名称 |
| Description | 否 | 当前步骤说明 |
| Status | 否 | 只有存在真实状态时使用 |

首版只支持线性 Horizontal / Vertical。存在分支、回流或泳道时，不用 Stepper 冒充复杂流程图。

## 3. 内部基础元素

内部基础元素不作为可独立选择的页面组件。

### 3.1 Icon Token

- 主要由 Feature 调用。
- 只有图标能提高辨认效率时才出现。
- 通用图标只使用 `references/common/material-symbols.md` 规定的 Material Symbols Outlined。
- 不得独立摆放以填补空白。

### 3.2 Tag

Tag 是附着于某个具体内容单元的短元信息，用于补充真实的状态、类别、优先级或选择建议。它不承担该单元的主题，也不建立新的内容层级。

AI 按信息职责识别 Tag，不能只按关键词、字号或文本长度判断：

1. 文案附属于某个 Card、步骤或内容项，而不是整页。
2. 文案回答“这个对象是什么状态、属于哪类、是否值得优先选择”，而不是“这个对象讲什么”。
3. 删除文案后，主体标题与内容仍然成立，但会失去一项判断或筛选信息。
4. 文案通常是短词或短语，不是完整说明句。

例如“推荐、可选、Beta、风险项”在承担上述职责时可以成为 Tag；页面标题、Card 标题、正文、CTA、Stat Label 和分组标题不属于 Tag。不能因为文本恰好出现“推荐”等词就机械套用 Tag。

- Tag 不是公开页面组件，只能由 Card 或具体内容组件调用。
- Tag 只表达输入内容或 AI 能从内容关系中明确判断出的真实元信息，不得为了装饰或填补空白自行添加。
- 共享层只定义语义；具体位置、字号、字重、颜色和占位规则由物料适配层定义。

### 3.3 Divider

- 默认关闭。
- 只有间距仍不足以区分连续条目时才由 Group 或 Collection 启用。
- 已有 Card 边界或充分留白时不再添加。
- 最后一项之后不显示。
- 颜色、粗细和上下间距由共享视觉角色与物料适配层映射。

### 3.4 Connector

- 首版只由 Stepper 内部调用。
- 只表达真实顺序，不作为装饰线。
- 起点、终点和长度由物料几何配方计算。

## 4. 容器与集合

### 4.1 Group

- 负责语义分组，不默认生成背景、描边和圆角。
- 默认按物料阅读方向组织相关内容。
- 最多允许两级语义分组；第二级必须对应真实子组。
- 如果小标题、位置、间距或 Divider 已足够，不增加第二级视觉边界。

### 4.2 Collection

Collection 负责同级组件的排列、统一间距和高度协调：

- **Stack**：同级组件纵向排列。
- **Row**：2–4 个同级组件横向排列为一行。
- **Grid**：多个同构组件按 2、3、4 列排列。

Collection 必须：

- 先取得子组件的理想尺寸，再确定统一行高和最终位置。
- 同一行保持等宽；同一行统一高度。
- 需要严格横向扫描时，整组统一为最大高度。
- 让无法整除的余量进入集合两侧留白，不偷偷拉宽单个单元。
- 保持同组组件类型、内容结构和视觉角色一致；真实分组或重点异化按 `references/common/design-foundation.md` 执行。

禁止瀑布流、同组任意不等宽、为填满最后一行拉宽个别组件，以及通过压缩字号强行增加列数。

### 4.3 Surface / Card

Surface 是底层视觉容器；Card 是市场与设计沟通中的可见名称：

```text
Card = Surface + 一个内容组件或 Group
```

- Card 不规定内部必须是标题、描述或图标。
- 一个内容分支只应用一次 Surface；默认禁止 Surface / Card 嵌套。
- 内部内容组件不得重复添加另一层背景、描边和圆角。
- 复杂信息确实存在两级边界时才允许例外，并在自检中记录语义理由。

## 5. 视觉角色

本节只定义角色，不定义 PPT、白皮书等物料的绝对尺寸。具体填充、描边、圆角和内边距由物料适配层映射，并在组件样稿阶段定稿。

| 角色 | 用途 |
|---|---|
| Bare | 透明背景、无描边；默认使用位置和间距建立关系 |
| Subtle | 弱背景或弱边界；仅靠间距不足以表达分组时使用 |
| Outline | 需要明确边界但不承担重点强调 |
| Accent | 使用当前页面主导色突出少量重点 |
| Inverse | 深色或表现型视觉背景上的反白状态 |

使用顺序：

1. 默认使用 Bare。
2. 需要分组时选择 Subtle 或 Outline。
3. 只有真实重点使用 Accent。
4. 只有背景要求反白时使用 Inverse。

视觉角色引用当前页面的颜色角色，不自行选择或轮换品牌三色。同一 Collection 默认使用同一视觉角色；单元异化继续遵守组内一致、点缀面积和语义记录规则。

## 6. 内容适配

“可选槽位”表示组件可以不含该信息，不表示内容一旦提供就可以为了适配版面被自动删除。

内容超出物料区域时按顺序处理：

1. 使用当前品牌和语言的真实字体测量内容。
2. 合并重复信息，或在不损失含义的前提下精简表达。
3. 切换当前组件已有的物料几何配方。
4. 调整 Collection 排列。
5. 切换页面或版面骨架。
6. 按真实语义边界拆页或分页。
7. 仍无法处理时，请用户决定是否删减内容。

禁止自动删除已有可选槽位、自动缩字填充、让同组某一项使用更小字号、裁掉文字或突破物料字号与间距下限。

## 7. 品牌与物料适配

### 7.1 品牌注入

- 明道云与 Nocoly 使用相同组件语义与组合规则。
- 生成时只读取当前品牌配置，取得字体、字重、Logo 和语言映射。
- 同一几何配方必须用当前品牌的实际字体重新测量，不能复用另一品牌的文本高度。

### 7.2 物料适配

物料适配层至少定义：

- 画布或纸张单位；
- 每个组件的合法几何配方；
- 有效区域与最小尺寸；
- 字号、间距、描边、圆角和内边距映射；
- 高度协调、分页或拆页；
- 渲染与验收流程。

当前状态：

| 适配层 | 状态 |
|---|---|
| PPT | 读取 `references/materials/ppt/components.md`，首版配方为 Specified |
| 白皮书 | 已建立 `references/materials/whitepaper/layouts.md`；组件适配层尚未建立，不得假定已有组件几何映射 |

组件只有经过真实物料样稿验证后才能从 `Specified` 标记为 `Validated`。
