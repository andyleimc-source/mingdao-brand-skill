# 生成预览前自检（必须循环执行到全部通过）

本文件适用于普通图片 / HTML 物料。**PPT 不执行本文件**，改走 `references/materials/ppt/export-qa.md`；**白皮书不执行本文件**，改走 `references/materials/whitepaper/layouts.md` 的 PDF 验收。适用物料在生成可视化预览（HTML/图片，调用 Artifact 或其他预览工具）之前，必须按下方七项逐条自检。**只要有一项不通过，就地修正后从头重新走一遍全部七项，不能只重查修改过的那一项**（改一处可能牵连其他项，比如删除重复文案后需要重新调整留白和字号层级）。七项全部通过，才能把预览展示给用户；不能把还没通过自检的草稿当作"先给用户看一版"。

## 1. 内容架构一致性（`generation-checklist-common.md`）

- 确认已记录当前品牌为明道云、Nocoly 或用户明确要求的联名，并且只加载了相应品牌配置。
- 对照生成前形成的内容方案，确认画布只包含“画布内容”，没有重新加入已合并、删除或移出画布的项目。
- 检查标题、活动标签、邀请语、CTA、品牌署名之间是否出现同义重复；Logo 已明确表达品牌时，不再重复添加没有新信息的“主办：品牌名”。
- 检查测试二维码、替换提醒、出血、内部状态等制作说明是否全部留在画布外。
- 检查观看顺序是否符合“第一眼看到 → 随后确认 → 最终行动 → 辅助信息”的传播层级。
- 检查二维码、Logo、远距离字号等功能最小值是否被误当成传播重要度；尺寸满足功能即可，不因此抢占第一视觉中心。
- 在画布外附完整的“原文 → 保留/合并/删除/移出画布”记录，供用户审阅。

**不通过判定**：品牌未确定，或非联名物料同时加载、混用两套品牌配置；画布出现语义重复、制作说明、已删除内容或无新信息的品牌署名；视觉顺序与内容方案不一致；因功能尺寸较大而错误提升传播层级；缺少画布外内容取舍记录。

## 2. 视觉元素必要性

- 逐一列出页面中的线、色块、图标、装饰图形及其他纯视觉结构元素。
- 对每一个元素强制提问：**“如果去掉它，信息会看不懂吗？”**
- 优先检查信息是否已经能够通过留白、布局疏密、字号、字重和对齐完成视觉分组；如果分组关系已经清楚，就不能再用纯视觉元素重复分组。
- 如果确有必要，必须写明该元素承担的不可替代功能，并验证当前形式已经是完成该功能所需的最小形式。

**不通过判定**：无法说明某个视觉元素对信息理解、可读性、操作识别或必要物理功能的直接作用；去掉后信息仍然清楚；元素只是为了“更丰富”“更有设计感”“更像一个分组”而存在；同一分组关系已由留白或排版表达，又被线、色块、图标重复表达。

## 3. 颜色

提取生成内容里用到的**所有色值**（背景色、文字色、边框色、装饰色——包括看起来很小的点缀色），逐个比对，只能是以下集合之一：

- 品牌三色（`design-foundation.md` 1.1 节）：`#1677FF` 品牌蓝 / `#E0E5EC` 云灰 / `#082C5E` 墨蓝
- 文字与图形功能色阶（1.1.1 节）：`#151A21` `#4E535C` `#767A80` `#C1C7CF` `#D6DBE2` `#E0E5EC` `#EBF0F6`
- 品牌蓝 10 级色阶（1.1.2 节）：`#F5F9FE` `#CADFFD` `#9EC5FC` `#71ABFC` `#4391FD` `#1677FF` `#0060E7` `#004DBA` `#003B8D` `#082C5E`
- 纯黑 `#000000`、纯白 `#FFFFFF`

继续按 `design-foundation.md` 1.1 节“单页主导色与同组配色规则”检查颜色关系：

- 海报类单页主视觉是否记录了用户确认的主背景色，成品是否与该选择一致；用户未指定且没有确认记录时不得通过。
- 明确记录本页主导色、非主导品牌色及其用途；有明显面积的非主导品牌色是否只有一种、合计是否不超过页面视觉面积的约 20%，是否形成第二视觉中心。
- 多页物料是否默认沿用同一个主导色；如按章节换色，是否来自用户明确要求，且同一章节内部保持稳定。
- 网格、卡片组、列表组和图标组中的同级单元是否继承同一组配色，背景、标题、边框、图标容器等同类元素是否保持一致，没有按单元或元素序号轮换品牌三色。
- 存在颜色分组、单个单元异化或两列对比时，是否记录了真实的信息语义与使用理由；颜色分组是否按整行、整列或完整子组保持组内一致；同一网格组是否默认最多只有一个异色单元。
- 两列对比若突破约 20% 限额，是否确因用户明确要求强对比，或不用整列异色底会显著降低理解效率，并记录了例外理由。
- 数据图表使用多色时，颜色映射是否稳定并优先使用品牌蓝色阶；图表配色是否没有扩散到标题、卡片和网格组件。

**不通过判定**：海报主背景色缺少用户确认记录或与确认项不一致；出现任何不在上述列表里的色值（包括 AI 随手生成的渐变色、阴影颜色、"看起来协调"但没有出处的色号），或功能色（成功/警告/错误等语义色）未经用户确认就自行引入；页面没有明确主导色关系，存在多个非主导品牌色、点缀面积超限或第二视觉中心；同组元素轮换品牌色；颜色分组、单元异化、两列强对比或图表多色没有真实语义、组内不一致或缺少例外记录。

## 4. 网格系统（`grid-system.md`）

- **模数**：所有边距/间距/列宽数值是否为布局模数（8px）的整数倍。允许的例外只有：字号本身（2px 模数，见第 5 项）、由公式算出的功能性尺寸（如标题贴边字号、贴边字号反推的容器宽度、Logo 按真实长宽比 `auto` 换算出的高度）——这些是公式产物，不强行二次取整凑 8px。
- **边距/安全区**：是否按物料专属安全区或 `grid-system.md` 默认边距公式计算，不是凭感觉给的像素值。
- **对齐**：同一文字块内的多行是否显式声明了 `text-align` 且方向一致（不能只依赖父容器 `align-items`）；不同的独立元素（logo/标签/时间等）是否被错误地耦合成"必须同一对齐方向"——按 `grid-system.md`"元素对齐"一节的作用域判断，独立元素允许各自选择对齐方式。
- **图片/Logo 比例**：是否有拉伸变形（渲染宽高比与源文件 viewBox 宽高比不一致）。

**不通过判定**：任意一个间距/边距/列宽数值不是 8px 整数倍且找不到"功能性尺寸豁免"的理由；文字块内多行对齐方式不一致或未显式声明；图片/Logo 被拉伸变形。

## 5. 字体与字号层级

- **品牌字体栈**：明道云逐字执行 `references/brands/mingdao.md`，Nocoly 逐字执行 `references/brands/nocoly.md`；禁止把两套字体栈混在同一非联名物料中，也禁止替换成品牌配置以外的字体名。
- **语言映射**：Nocoly 检查 `en`、`zh-CN`、`zh-TW`、`zh-HK`、`ja`、`ko` 是否分别使用 Inter 或正确的 Noto Sans CJK 地区实例；不能用 SC 字形覆盖所有 CJK 内容。明道云检查是否完成苹方预检，并在缺失时显示提示后改用 Source Han Sans CN。
- **字号**：是否为原子尺寸（2px）的整数倍。
- **字重层级**：执行当前品牌配置的真实字面映射，不合成不存在的字重；明道云苹方标题用 Semibold，降级 Source Han 标题用 Bold，Nocoly 只用 400 / 500 / 700。
- **字号种类**：同一画面是否超过四种字号。
- **共享层级**：字号比例和字号下限遵守 `design-foundation.md` 1.2 节。
- **多语与折行**：固定画布或定高物料按 `grid-system.md` 的“多语版式的纵向留白”和“定高版面的富余留白”检查多语版式间距；所有 HTML 排版按 `design-foundation.md` 1.2 节“中文折行与孤字”检查末行字数与断行方式。
- **Nocoly HTML 字体嵌入**：生成后必须运行 `python3 scripts/common/font_assets.py embed-html output.html`，再运行 `python3 scripts/common/font_assets.py validate-html output.html`；检查结果必须为 `OK`，文件中不得残留远程字体 CDN。

**不通过判定**：品牌字体栈或语言实例错误；字体缺失后静默替换；Nocoly HTML 未嵌入字体、嵌入资源校验失败或仍依赖远程字体 CDN；字号非 2px 整数倍；使用合成字重或当前品牌未定义的字重；字号种类超过四种；多语定高版式使用浏览器平摊富余留白；正文使用 `text-wrap: balance`；多行文本的中文末行少于 5 字或英文末行少于 8 字符。

## 6. Logo（`references/common/logo.md`）

- **宽度**：是否按 `logo.md` 公式重新计算（确定基准宽度 → 按分档占比取值 → 就近取整到 8px 模数），不是凭感觉给的数值。
- **高度**：是否用 `height: auto` 按所选 Logo 源文件的真实 viewBox 长宽比换算，没有手动指定一个可能导致形变的高度值。
- **品牌匹配**：源文件是否来自当前品牌配置；非联名物料是否混入另一个品牌或其子产品组合标志。
- **源文件与颜色**：是否直接调用 `assets/common/logos/` 下的官方文件；如做了反白或换色处理，是否符合 `logo.md` 的允许范围。
- **安全区**：Logo 高度 1/4 的四周留白是否被其他元素侵占。

**不通过判定**：Logo 与当前品牌不匹配；Logo 宽度不是套公式算出来的；高度手动指定导致比例失真；用了非官方文件或改成了允许范围外的颜色；四周留白不足。

## 7. 图标（`references/common/material-symbols.md`）

- 画面出现通用图标时，是否只使用本地 Material Symbols Outlined，且图标名存在于 `assets/common/icons/material-symbols/codepoints.txt`。
- HTML 是否从本地 WOFF2 或内嵌 data URI 加载字体，没有使用 Google Fonts CDN；图标是否保留 `material-symbols-outlined` 类、`data-material-symbol` 属性和合法 ligature 名。
- 是否统一使用 `FILL=0`、`wght=400`、`GRAD=0`、`opsz=24`；只有明确表达选中/开启状态时才把 `FILL` 改成 1。
- 是否已经执行资产校验与交付物校验：

```bash
python scripts/common/material_symbols.py verify-assets
python scripts/common/material_symbols.py validate output.html --require-icons
```

没有通用图标时，本项记录“不适用”，并去掉 `--require-icons` 运行校验；不得为了通过检查而添加无意义图标。Logo、二维码、照片、品牌插画和数据图表不按通用图标处理。

**不通过判定**：出现其他图标库、Emoji 图标、手绘 SVG 图标或远程图标 CDN；图标名不在白名单；字体未本地加载；参数无理由混用；校验脚本退出码非 0。

---

自检时逐项写出"数值/判定依据 → 结论"，不要只给"通过/不通过"的结论而不说依据——这样才能在不通过时准确定位是哪个数值、哪条规则出的问题，直接修正，而不是整体重做。
