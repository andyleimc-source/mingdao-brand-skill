# 生成前通用内容关卡（软确认）

适用于所有品牌物料。目标是在设计开始前确定“说什么、先说什么、哪些不该出现在画布里”，同时避免把 AI 应完成的专业判断转嫁给用户。

本文件是生成前内容处理、信息层级和提问规则的唯一来源。物料专属文件只补充无法通用化的必要事实（如实际尺寸），不得复制另一套确认逻辑。

## 1. 总原则

- AI 默认完成内容去重、画布内外分层、信息排序和常规设计判断。
- 内容明确时采用软确认：展示简短任务理解摘要后直接生成，不等待用户回复“确认”。
- 存在会实质改变传播含义或交付结果的歧义时暂停；海报类单页主视觉的背景色、PPT 封面颜色和白皮书封面颜色未由用户指定时，也必须进入第 5 节的颜色确认关卡。
- 能通过用户已提供的信息、项目文件、品牌资产或工具查明的事实，先自行查明，不向用户提问。
- 不得为了“流程完整”固定询问 Logo、文字等问题；背景色只在第 5 节规定的物料与页面角色中固定确认。

## 2. 先检查输入，不要逐项照搬

把用户输入拆成四类：

1. **传播内容**：标题、时间、地点、卖点、行动指令等可能进入画布的信息。
2. **品牌资产**：Logo、子品牌、联名关系、产品截图、照片等。
3. **制作说明**：测试二维码、正式发布前替换、出血、印刷备注、文件命名等只服务于制作过程的信息。
4. **物料事实**：尺寸、方向、发布渠道、观看距离等影响交付结果的条件。

用户列出的每一项都只是输入，不等于必须原样出现在画布中。

### 常见输入的默认处理

- **品牌与 Logo**：先按 `SKILL.md` 确定明道云、Nocoly 或明确联名；只读取对应品牌配置，再从 `assets/common/logos/` 选择与背景匹配的官方版本。仅在子品牌、联名关系或品牌归属存在歧义时提问。
- **文字**：使用用户提供的真实事实，不编造关键事实；缺失内容只有在命中第 5 节暂停条件时才提问。
- **背景**：AI 先按 `design-foundation.md` 1.1 节结合场合、内容密度和传播目标形成推荐。普通内容页和非海报物料可以自动采用；海报类单页主视觉、PPT 封面和白皮书封面必须按第 5 节提供颜色选项并取得用户确认。
- **二维码**：测试/替换提醒属于制作说明，放在画布外；二维码在画布中的尺寸按对应规范计算。

## 3. 生成内部内容方案

### 3.1 内容取舍

逐项归入以下状态：

- **保留**：承担独立且必要的信息功能。
- **合并**：与其他内容语义重复，合并进更清晰、层级更高的一项。
- **删除**：不增加新信息，或已由 Logo、标题、图片等明确表达。
- **移出画布**：制作提醒、替换说明、出血备注、内部状态等。
- **待确认**：命中第 5 节暂停条件，AI 无法安全决定。

优先消除：

- 标题、活动标签、邀请语之间的地域/受众/活动类型重复；
- Logo 已明确表达主办品牌后再次出现的“主办：品牌名”；
- “报名方式”与明确 CTA 之间没有新增意义的重复标签；
- 测试二维码、替换提醒等制作信息进入正式画布；
- 仅为了填满版面而添加的辅助文案。

### 3.2 信息层级：传播重要度

按观众的阅读与行动顺序确定：

1. **第一眼看到**：物料唯一的核心信息。
2. **随后确认**：支持理解或决策的重要事实。
3. **最终行动**：希望观众完成的动作。
4. **辅助信息**：删除后不影响核心理解，但确有补充价值的内容。

视觉层级必须服从这条顺序，不得把所有输入平均分配权重。

### 3.3 信息层级：功能性约束

二维码最小尺寸、Logo 安全尺寸、远距离可读字号、出血和收卷安全区等是功能要求，不等同于传播重要度。

例如二维码因扫码距离而尺寸较大，不代表它应成为第一视觉中心。分别记录“传播优先级”和“功能最小值”，不要混成一条排序。

## 4. 面向用户的软确认摘要

内容明确且不命中第 5 节颜色确认关卡时，在生成前展示简短摘要：

```text
品牌：<明道云 / Nocoly / 明确联名>
目标：<观众看完后应理解并完成什么>
第一眼看到：<核心信息>
随后确认：<重要事实>
最终行动：<CTA；没有则写“无”>
自动处理：<合并/删除/移出画布的数量与简述>
待确认：无，按此直接生成
```

摘要用于让用户低成本发现方向错误，不要求回复确认。完整的“原文 → 保留/合并/删除/移出画布”记录放在预览后的画布外说明中，不占用设计画布。

命中颜色确认关卡时，把最后两行替换为：

```text
颜色建议：<推荐颜色名称与 HEX>；<一句与场合、内容或传播目标相关的理由>
颜色选项：<推荐项置于第一位> / <其他允许颜色>
待确认：请选择背景或封面颜色；确认后生成
```

## 5. 必须暂停提问或确认的情况

以下四类真实歧义允许暂停：

1. **核心目标冲突**：无法判断应突出活动主题、产品卖点还是行动指令。
2. **受众或行动不明确**：不知道给谁看，或看完希望对方做什么，且不同答案会改变内容结构。
3. **关键事实缺失或矛盾**：日期、地点、尺寸、价格、联系方式等无法查明或合理推断，并会影响交付正确性。
4. **品牌归属存在歧义**：通用品牌、子品牌、联名关系等不同选择会改变 Logo 和品牌表达。

另外，以下视觉偏好必须确认：

5. **指定物料的主背景色尚未确认**：适用于海报类单页主视觉（数字海报、活动海报、展板、易拉宝、KV 等）以及 PPT、白皮书的封面。用户没有指定颜色时，AI 必须先依据 `design-foundation.md` 1.1 节推荐一种颜色，再提供品牌蓝 `#1677FF`、云灰 `#E0E5EC`、墨蓝 `#082C5E`、纯白 `#FFFFFF` 四个选项；推荐项排第一并说明理由，等待用户选择后再生成。用户已经明确指定颜色，或已经明确指定必须使用的图片、截图或视频作为完整背景且不存在独立底色选择时，不重复提问。系列海报只确认整组的主背景色一次；PPT 和白皮书只确认封面颜色一次，普通内容页继续按各自规范处理。

不符合以上五类的问题禁止询问用户。语义去重、制作说明移出画布、信息层级、字号、间距和常规视觉结构仍由 AI 判断；颜色确认不能退化成让用户自行完成配色方案，AI 必须先给出专业建议。

命中暂停条件时：

- 一次只问一个问题；
- 说明该问题会改变什么；
- 同时给出推荐答案；
- 得到回答后重新检查是否仍有下一项真实歧义；
- 不批量抛出设计术语或让用户从零完成信息架构。

颜色确认的提问只包含一个选择：背景或封面主色。Logo 标准版/反白版在用户确认颜色后按 `references/common/logo.md` 自动匹配，不把 Logo 版本作为第二个常规问题。

## 6. 传递给生成与预览检查的内容方案

开始设计前保留以下内部结果，供 `pre-preview-self-check.md` 对照：

```text
品牌：
目标：
受众与行动：
已确认的海报背景或封面颜色：
传播层级：第一眼 / 随后确认 / 最终行动 / 辅助
画布内容：
移出画布：
自动合并或删除：
待确认：
功能性约束：
```

生成时不得重新加入已删除或已移出画布的内容，也不得用纯视觉元素重复表达已经由内容层级和留白建立的分组。
