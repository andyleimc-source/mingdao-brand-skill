# Logo 使用与尺寸计算

适用于明道云与 Nocoly 的所有物料。品牌身份和具体 Logo 文件先按 `references/brands/mingdao.md` 或 `references/brands/nocoly.md` 确定；本文件只规定两个品牌共同遵守的 Logo 使用和尺寸规则。

## 通用使用规则

- Logo 统一使用 `assets/common/logos/` 下的官方源文件或按本文件规则保存的反白派生文件；除“缺少反白文件时生成派生版”外，禁止 AI 重新生成、临摹、拆解或重组。
- 标准版与反白版的选择执行下方“Logo 资产选择与背景适配”；有官方反白文件时必须直接使用，不得从标准版重复生成。
- Logo 四周安全区为实际显示高度的 1/4。
- 印刷物料最小宽度为 20mm。
- 水印版颜色固定为 `#C1C7CF`，只用于文档、PPT 等需要弱化品牌存在感的场景，不用于封面和 KV。
- Logo 颜色以官方源文件为准；背景适配时唯一允许的派生处理，是按本文件规则为缺少反白文件的 Logo 生成纯白版。水印版继续执行上一条独立规则。
- 禁止拉伸、投影、描边、渐变、置于低对比或复杂图案背景、擅自改变图形与标准字的位置关系，以及把 Logo 当作大面积装饰纹样。

## Logo 资产选择与背景适配

### 0. 按设计场景自动选标志（场景 → 背景 → 空间，三步走完再动手）

依据设计组《明道云与Nocoly品牌与产品标识使用指南》（2025-06-12）。AI 按下列顺序自动判断，**不逐项询问用户**；只有主品牌（明道云 / Nocoly）无法从输入和上下文判断时暂停问一次。

**第一步：场景 → 标志类型**

| 场景 | 标志类型 |
|---|---|
| 公司整体形象：企业官网首页、公众号/视频号头像、对外商务文件、品牌海报与展架、媒体报道、名片、企业介绍 PPT 封面 | 品牌标（明道云 / Nocoly） |
| 产品首次对外介绍、伙伴推广、联名活动、投标招标、商务提案 PPT、合同附件、市场活动物料、活动展板 | 品牌 + 产品组合标（`子产品 logo/<品牌>&HAP|HDP`） |
| 产品本身：产品官网页、应用内界面、产品操作界面、产品介绍手册、产品演示视频、产品培训资料、使用说明、社区文章/教程里的产品标识 | 独立产品标（`HAP-*` / `HDP-*`） |
| 明道云与 Nocoly 同时出现的联名物料 | `mingdao&nocoly-*` |
| 浏览器标签图标、网站小图标等极小位置 | 图形标（`mingdao-ming-icon.svg`、`mingdao-ming*.svg`、`nocoly-n*.svg`）；**不用于头像** |
| 文档、PPT 内页等需要弱化品牌的水印 | 水印灰版（`*_watermark.svg`，`#C1C7CF`）；不用于封面和 KV |

场景同时命中多行时，取「物料的主要传播目的」那一行；拿不准时默认组合标（它同时带出品牌和产品，出错代价最小）。

**第二步：背景 → 颜色版本**：按下方第 2 节的固定映射选标准版或反白版（`_dark` / `-dark`）。

**第三步：空间 → 形状版本**

| 放置位置 | 选用 |
|---|---|
| 常规横向位置 | 明道云用带网址完整版 `mingdao-logo-*`；产品标用横版 |
| 扁横幅、竖向空间紧张 | 明道云用不带网址简版 `mingdao` / `mingdao-dark`；产品标用横版 |
| 竖长或接近方形的位置 | 产品标用竖版 |
| 极小尺寸（小于印刷最小宽度 20mm 或屏幕 32px 以下） | 图形标 |

**位图交付**：每个 SVG 在 `assets/common/logos/png/` 下有同名透明底 PNG（长边 2000px），PPT、Word 等不能直接用 SVG 的场景优先取现成 PNG，不用每次再转。

### 1. 先确定品牌关系

- 用户选择 HAP 或 HDP 且不属于「产品本身」场景时，对外物料默认使用“当前主品牌 + 子产品”的官方组合 Logo，并把它作为画面中的唯一 Logo；不得再额外放置主品牌 Logo，也不得默认改用独立 HAP/HDP Logo。
- 当前物料已经确定主品牌时，直接继承该品牌：明道云物料选用 `子产品 logo/明道云&HAP.svg` 或 `子产品 logo/明道云&HDP.svg`，Nocoly 物料选用 `子产品 logo/nocoly&HAP.svg` 或 `子产品 logo/nocoly&HDP.svg`。
- 用户只说使用 HAP/HDP、但上下文无法确定主品牌时，必须暂停并询问搭配明道云还是 Nocoly；不得擅自默认主品牌，也不得用独立 HAP/HDP Logo 规避选择。
- 用户明确要求“独立 HAP/HDP Logo”，或第 0 节第一步判定为「产品本身」场景时，使用 `HAP-横版.svg`、`HAP-竖版.svg`、`HDP-横版.svg` 或 `HDP-竖版.svg`（及对应 `_dark` 反白版）。横版与竖版按第 0 节第三步的放置位置自动选择，不旋转、不重排。

### 2. 再按背景选择标准版或反白版

四种官方满版背景使用固定映射，不逐次重新判断：

| 背景 | 使用版本 |
|---|---|
| 纯白 `#FFFFFF`、云灰 `#E0E5EC` | 标准版 |
| 品牌蓝 `#1677FF`、墨蓝 `#082C5E` | 反白版 |

照片或其他非纯色背景按 Logo 实际放置区域判断：

- 区域均匀、浅色、低饱和时使用标准版。
- 区域为深色或高饱和时使用反白版。
- 区域明暗混杂或纹理复杂、任一版本都不能稳定辨认时，必须更换或调整背景；不得给 Logo 增加纯色承载区，也不得为了迁就背景修改 Logo。

`3:1` 只作为本项目在非纯色背景上检查 Logo 是否可稳定辨认的内部基线，参考 WCAG 2.2 的非文本对比度门槛；Logo 属于 WCAG 的品牌标志例外，因此这里不把该数值表述为 Logo 的 WCAG 合规要求。固定的四种官方背景仍直接按上表选择，不展开多色 Logo 的逐色计算规则。

### 3. 缺少反白文件时生成派生版

- 先检查 `assets/common/logos/` 及其子目录。已经存在官方 `dark` 版本时必须原样使用，包括文件自带的颜色和透明度，不得重新着色或“优化”。
- 确认没有反白文件时，允许 AI 从标准 SVG 生成一个独立的纯白派生文件，命名为 `<原文件名>_dark.svg`，保存到原文件所在目录；不得覆盖或改写标准版。
- 生成反白版时只处理 `fill`：把所有可见图形中已明确声明的非 `none` 填充色统一改为 `#FFFFFF`；`fill:none` 保持不变，`stroke` 不处理。
- 除上述 `fill` 颜色替换外，源文件的路径、尺寸、`viewBox`、透明度、图层顺序、间距和组合关系必须完全保留。禁止调整比例、轮廓、描边、透明度或任何几何结构。
- 标准 SVG 的可见图形必须显式声明 `fill`，黑色文字使用 `#000000`；不得依赖 SVG 默认黑色。若源文件仍有未声明 `fill` 的可见图形，先补齐或取得合格源文件，再生成反白版，禁止由 AI 猜测图形语义。

## 尺寸计算（按画布宽度分级）

目的是让 Logo 占比有统一基准可依据，不同物料、不同人生成时不再凭感觉给一个数字——避免出现"同样是给品牌露出，这个物料 Logo 偏小、那个物料偏大"的不一致。

## 计算步骤

**1. 确定基准宽度**（画布宽度扣掉左右边距的可用宽度）：
- 物料如果有自己的专属安全区（比如公众号头条封面的 780px 安全区），直接用该宽度；
- 没有专属安全区的物料，按 `grid-system.md`「边距计算规则」算出实际边距，用 `画布宽度 − 2×实际边距` 作为基准宽度。
两者的优先级和 `grid-system.md` 里"物料自定义边距优先于网格默认边距"是同一条规则，这里不重复定义一套。

**2. 按基准宽度分三档取占比**（画布越宽，Logo 占比越小；三档在 1080px / 1920px 两个分界点上首尾相接，不会跳变）：

| 基准宽度 | 占比 | 取值方式 |
|---|---|---|
| < 1080px | 1/8 – 1/6 | 区间内按物料实际需要选取——竖向空间紧张（画布矮、扁横幅）取下限 1/8，空间宽裕取上限 1/6 |
| 1080px – 1920px | 1/6 – 1/12 之间线性插值 | 按下方公式计算，画布越宽插值结果越接近 1/12 |
| > 1920px | 1/12 – 1/8 | **优先用下限 1/12 生成**，只有需要强化品牌露出（比如展板、KV 这类以品牌曝光为主诉求的物料）才取到上限 1/8 |

1080px – 1920px 区间的插值公式：
```
占比 = 1/6 + (1/12 − 1/6) × (基准宽度 − 1080) ÷ (1920 − 1080)
```

**3. 算 Logo 宽度，取整到布局模数（8px）**：
```
Logo 宽度（未取整） = 基准宽度 × 占比
Logo 宽度 = 就近取整到布局模数（8px）的整数倍
```

**4. 换算 Logo 高度，不强行凑模数**：
```
Logo 高度 = Logo 宽度 ÷ 该 Logo 源文件的真实长宽比（viewBox 宽:高）
```
用 CSS 时写 `width: 计算出的宽度px; height: auto;`，交给浏览器按 SVG 原始比例换算，不手动指定高度——保证零形变，这条和 `grid-system.md`「图片裁切规则」里"不允许拉伸挤压凑比例"是同一原则。高度不必是 8px 的整数倍，属于由宽度和长宽比共同决定的派生值，不是独立设定的布局尺寸。

**5. 反推安全区留白**：按本文件"Logo 高度的 1/4"，用第 4 步算出的实际高度（不是源文件的固有像素高度）计算四周留白。

## 选哪个 Logo 源文件

`assets/common/logos/` 下同一品牌可能有多个版本，长宽比不同（见该目录 `README.md`）。画布竖向空间紧张时（比如公众号头条封面这类扁横幅），优先选长宽比更"宽"的简版（如 `mingdao.svg`/`mingdao-dark.svg`，无图形标、无网址），同样的宽度占比能显著降低实际占用的高度；不选哪个版本，本公式的宽度计算方式都不变，只是第 4 步用的长宽比不同。

## 示例（公众号头条封面，安全区 780px，选用简版 Logo 比例 200.14:62 ≈ 3.23:1）

```
基准宽度 780px < 1080px → 占比区间 1/8–1/6
竖向空间紧张 → 取下限 1/8
Logo 宽度（未取整）= 780 ÷ 8 = 97.5px → 就近取整到 8px 模数 = 96px
Logo 高度 = 96 ÷ 3.23 ≈ 29.7px（auto，不取整）
安全区留白 = 29.7 ÷ 4 ≈ 7.4px
```

## 示例（1920px 宽画布 / 16:9 PPT，无专属安全区）

基准宽度必须用 `grid-system.md`「边距计算规则」实际算一遍，不能拍脑袋给：

```
参考边距 = 1920 × 6% = 115.2 → 就近取整到 8px = 112px
最小边距 = max(32, 1920 × 4% = 76.8) → 向上取整到 8px = 80px
实际边距 = max(112, 80) = 112px
可用宽度候选 = 1920 − 224 = 1696px
列宽 = floor((1696 − 11×8) ÷ 12) = floor(134) → 向下取整到 8px = 128px
零头 = 1696 − (12×128 + 88) = 72px，平分计入左右边距 → 每侧 112 + 36 = 148px
基准宽度 = 1920 − 2×148 = 1624px
```

这与 `references/materials/ppt/layouts.md` 写死的“1920px 画布：左右边距 148px、每列 128px、gutter 8px”完全一致。继续算 Logo：

```
基准宽度 1624px，落在 1080–1920px 区间
占比 = 1/6 + (1/12 − 1/6) × (1624 − 1080) ÷ (1920 − 1080)
     = 0.16667 + (−0.08333) × 544 ÷ 840
     ≈ 0.16667 − 0.05397 ≈ 0.11270（约等于 1/8.9）
Logo 宽度（未取整）= 1624 × 0.11270 ≈ 183.0px → 就近取整到 8px 模数 = 184px
Logo 高度 = 184 ÷ 2.043（mingdao-logo-light.svg 实测比例）≈ 90.1px
安全区留白 = 90.1 ÷ 4 ≈ 22.5px
```
