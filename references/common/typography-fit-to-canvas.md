# 标题字号计算（按画布尺寸 + 最长行文字宽度）

适用于任何在固定像素画布上放大标题/主视觉文字的物料（展板、易拉宝、KV、手机海报、公众号封面等）。目的是避免两种常见错误：字号凭感觉给得太小（画面软、不够分量），或字号顶满画布边缘（太挤、没有留白）。

## 计算步骤（主流程）

**1. 算可用宽度**

画布宽度扣掉左右安全边距。边距按 `grid-system.md`「边距计算规则」计算——参考边距取画布宽度 6%，就近取整到 8px 整数倍，且不低于最小边距下限 `max(32px, 画布宽度×4%)`；具体物料如有自己的安全区规则，以该物料规则为准，但同样不能低于最小边距下限（常见物料的安全边距起点见文末「常见物料的安全边距参考」）。

```
可用宽度 = 画布宽度 − 2×实际边距
```

**2. 估算最长一行文字的宽度**

用"字符数 × 单字宽度系数"估算，不同字符类型系数不同：

```
最长行宽度(em) = 中文/日文字符数 × 1.0
              + 英文字母/数字字符数 × 0.6
              + 标点/空格字符数 × 0.5
```

**3. 算"贴边字号"**

让最长行刚好撑满可用宽度时的字号，同时除以 1.08 留出安全余量——字体实际字宽、字间距通常比估算值略宽，零余量会导致实际渲染比估算宽，触发意外换行。

```
贴边字号 = 可用宽度 ÷ (最长行宽度(em) × 1.08)
```

**4. 用画布宽度的比例给贴边字号设上限/下限**

防止短文案被拉得过大、长文案被压得过小：

```
上限字号 = min(贴边字号, 画布宽度 × 14%)
下限字号 = 画布宽度 × 6%
```

**5. 取目标字号并取整**

不要无脑取上限——那是贴边的临界值，实际取「贴边字号」和「画布上限的 75%」两者中较小的一个：文案短、贴边字号本来就大时，会被 75% 封顶，避免顶满安全区；文案本来就长、贴边字号已经比较克制时，不再额外二次缩小。

```
目标字号 = min(贴边字号, 画布宽度 × 14% × 75%)
最终字号（未取整） = clamp(目标字号, 下限字号, 画布宽度 × 14%)
最终字号 = 就近取整到原子尺寸（2px）的整数倍
```

> 这一步取整只是消除小数点（比如 113.4px → 114px），偏差在 ±1px 以内，不属于「为了凑模数而压缩变形」，不受 `grid-system.md`「功能性尺寸优先」条款保护的豁免影响——那条豁免针对的是不能为了凑十几到二十几像素的品牌字号阶梯（`design-foundation.md` 1.2 节的 14×N 体系）而牺牲贴边效果，不代表可以出现带小数的字号。

**6. 反推标题容器宽度**

从最终字号反推，同样带上 1.08 的余量——余量已经在第 3 步的贴边字号里扣过一次，这里反推回去正好还原，容器宽度天然不会超过第 1 步的可用宽度，不需要再额外检查。

```
标题容器宽度（未取整） = 最终字号 × 最长行宽度(em) × 1.08
标题容器宽度 = 向上取整到布局模数（8px）的整数倍；
              如果向上取整后超过第 1 步的可用宽度，改为向下取整
              （这种情况通常出现在贴边字号本来就接近可用宽度上限时，向下取整损失的 8px 以内余量会在后续 Figma 微调阶段被吸收，不会实际触发换行）
```

容器宽度属于布局尺寸，按 `grid-system.md` 的两级模数规则用 8px 取整，不用字号的 2px 颗粒度。

## 特殊情况

**情况一：目标字号低于下限字号**

说明文案太长，塞不进一行还保持可读。不要继续往下压字号突破下限，而是请用户判断二选一：
- 把这行拆成两行，分别按各自最长片段重新算一次贴边字号；
- 请用户精简文案，缩短字符数后再算。

**情况二：某一行带局部强调色块**

见 `design-foundation.md` 1.1 节「局部强调的配色规则」，色块反转会给文字加内边距。容器宽度不能只按纯文字算，要把色块内边距也加进去，取所有行里需求最大的那个。色块内边距本身属于布局尺寸，取布局模数（8px）的整数倍（比如 8px、16px），禁止凭感觉给值：

```
该行总需求宽度 = 该行文字宽度(em) × 最终字号 × 1.08 + 色块左右内边距之和（8px 的整数倍）
标题容器宽度（未取整） = max(各行总需求宽度)
标题容器宽度 = 向上取整到布局模数（8px）的整数倍
```

容易漏的点：色块内边距是「额外加出来的宽度」，不在第 2 步的文字宽度估算里，必须单独加，不能指望第 3-6 步的公式自动把它算进去——那几步全程都只算纯文字。


## 使用须知

**这套公式给的是一个可用的起始字号，不是像素级精确排版。** 中文字体实际字宽会因字重、具体字形略有出入（比如逗号、引号比估算更窄）。套用公式算出字号后，仍要在 Figma 里实际排一次文字，肉眼确认有没有贴边或还有富余，微调 ±10% 以内都算正常。

**已知局限：贴边字号如果刚好卡在 75% 封顶阈值以下（比如差 1-2px 没触发封顶），标题会顶满整个可用宽度**，安全区/画布内部几乎没有留白——公众号头条封面就实测踩过这个坑。如果物料本身有独立安全框、且对留白比例有明确要求，可以不套用这套"贴边字号"公式，改用更直接的"标题宽度 = 画布宽度 × 固定比例"（比如头条封面用 64%），留白随画布等比缩放、不会被贴边逻辑吃掉，具体写法见 `wechat-headline-cover.md`。两种方法都合规，按物料实际需要选，不是后者取代前者。

## 常见物料的安全边距参考

供第一步「算可用宽度」取「实际边距」时参考。以下比例均需按 `grid-system.md`「边距计算规则」就近取整到布局模数（8px）的整数倍，且不低于最小边距下限 `max(32px, 画布宽度×4%)`——比例是起点，不是免检的最终值。

| 物料 | 左右安全边距（占画布宽度） |
|---|---|
| 展板 | 6%（默认值，无特殊要求可直接用） |
| 易拉宝 | 参照 `references/materials/print/print-rollup-banner.md` 已有的排版禁忌，边距可适当放宽到 10-12% |
| 手机海报 / 竖版视频 | 已有专用安全框，见 `references/materials/digital-social/mobile-poster-vertical-video.md`，不用这里的 6% 默认值 |
