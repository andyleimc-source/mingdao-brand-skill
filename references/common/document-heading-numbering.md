# 文档标题层级与章节编号规范

生成 Word / DOCX、国际化或多语言产品文档、规范、协议、白皮书及其 PDF 版本时读取本文件。本文件只管理标题层级与章节编号，不管理正文列表编号、页码、表格编号或证据项编号。

## 1. 默认：标题不编号

没有明确引用、定位或顺序执行需求时，关闭章节编号，统一使用以下语义层级：

| 样式 | 语义角色 |
|---|---|
| H1 / Heading 1 | Page title |
| H2 / Heading 2 | Section |
| H3 / Heading 3 | Subsection |
| H4 / Heading 4 | Minor subsection |

`Page title`、`Section`、`Subsection`、`Minor subsection` 是语义角色说明，不是需要写进文档的固定英文。实际标题按内容语言书写；不得为了“看起来有结构”手工添加数字、罗马数字或其他前缀。

Word / DOCX 必须使用原生 Heading 1–4 样式建立文档大纲；不得用加粗正文、普通列表或手工字号模拟标题。目录从标题样式生成，不依赖章节编号。

## 2. 是否启用编号

判断问题只有一个：**编号是否用于引用、定位或按顺序执行，而不只是装饰结构？**

出现以下任一真实需求时启用或建议启用编号：

- 需要精确引用章节，例如“请参见 3.2.1 权限设置”。规范、协议、需求文档和设计系统文档通常属于此类。
- 章节存在明确先后关系，例如安装步骤、迁移流程或操作指南，读者必须知道先后顺序。
- 文档很长、层级很深，脱离搜索或侧边导航后定位成本明显增加。
- 多人协作时经常按章节讨论、评审和记录修改，例如“2.3 需要调整”。
- 文档会导出、打印或脱离网页导航阅读，例如 PDF、合同、白皮书和规范文档。

前两项属于强编号需求；后三项根据文档长度、协作方式和离线阅读场景判断。仅有“显得正式”“更像目录”或“看起来更有层次”不构成启用理由。编号模式在整份文档开始生成前确定；除附录或受外部模板约束的部分外，不在同一正文中混用编号与无编号章节。

## 3. 编号格式

需要编号时统一使用 Arabic decimal numbering：

| 样式 | 格式示例 |
|---|---|
| H1 / Heading 1 | `1 Title` |
| H2 / Heading 2 | `1.1 Title` |
| H3 / Heading 3 | `1.1.1 Title` |
| H4 / Heading 4 | `1.1.1.1 Title` |

- 使用 ASCII 阿拉伯数字 `0–9` 和半角句点 `.` 分隔层级；编号末尾不增加句点。
- 新 H1 递增一级编号；H2、H3、H4 分别在新的上级标题下重新从 1 开始。
- 不跳级，不出现有 `1.1.1` 却没有对应 `1.1` 的结构。
- 不混用 `I / II / III`、`A / B / C`、中文数字或全角标点。

Roman numerals `I / II / III` 不作为产品文档默认样式。仅在法律文件、政策文件、学术提纲、合同或特殊出版 / 视觉场景中，并且用户、既有模板或正式出版惯例明确要求时使用；启用时记录例外依据，并在同一作用域内保持一致。

## 4. Word 与国际化实现

- 无编号模式：Heading 1–4 不绑定多级列表，并清除模板继承的自动编号；不得在标题文本中保留手工编号。
- 编号模式：建立一套多级列表并绑定 Heading 1–4；编号由文档样式生成，不把 `1.2.3` 写死在标题字符串或翻译资源中。
- 交叉引用优先使用 Word 域、书签或稳定标题 ID，使标题增删后引用和目录可以更新；不得只维护肉眼可见的手工数字。
- 多语言版本结构一致时保持相同章节编号，只翻译标题文本；结构发生增删时重新生成该语言版本的编号、目录和交叉引用，不沿用失效编号。
- 所有语言默认保持 ASCII 十进制编号和半角句点，不把编号本地化为中文数字、全角数字或罗马数字。RTL 文档保持编号字符的逻辑顺序，不反转层级。

## 5. 交付检查

- 全文只采用一种正文编号模式；任何 Roman numerals 例外都有明确依据。
- Heading 1–4 的语义层级连续，没有跳级或用正文样式冒充标题。
- 编号开启时递增与重启正确，目录、正文标题、书签和交叉引用一致。
- 编号关闭时标题、目录和导航窗格均不残留模板编号。
- 国际化版本的标题层级、编号模式和引用关系与实际内容结构一致，不因翻译语言改变编号体系。
